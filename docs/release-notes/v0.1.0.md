First pre-release of deckfold.

deckfold turns the HTML export of a presentation into a single HTML file that runs without a folder and without a network connection. The player of the source stays unchanged, so transitions and animations look the same. deckfold adds a start screen, a presenter view with previews, notes, timer and slide overview, auto mode, a choice of screens for the audience window and the presenter view, and control by keyboard or presentation clicker.

Supported sources: Keynote HTML exports and claude.ai slide decks. PowerPoint and Google Slides decks work through Keynote (open the PPTX in Keynote and export it as HTML). Other HTML files can be embedded with `--generic`, without presenter view and auto mode.

## What is tested

- Go unit and CLI tests on five GitHub runners: Linux x64 and arm64, Windows x64 and arm64, macOS arm64.
- A smoke test of the native binary on all five runners: `--version` and a conversion of a small fixture with embedding and duplicate removal.
- On Linux the smoke test also runs as an unprivileged user. Windows and macOS runners have elevated rights, so there the test shows that the binaries run, not that they run without admin rights.
- The macOS Intel binary (`darwin-amd64`) passed the smoke test through Rosetta on the macOS arm64 runner; it has not run on an Intel Mac.
- The full browser tests (presenter view, previews, auto mode, recovery, pixel comparison with the original, a 300 MB file) ran on macOS in Chrome and WebKit with local sample decks.

## Not tested yet

- A presentation with two real screens (window placement, full screen in the audience window, audio without a click). `docs/manual-test.md` has the checklist.
- Firefox.
- The browser tests on Windows and Linux.
- Keynote decks with builds, video, audio or self-playing timing.

## Known limits

- Keynote does not export presenter notes, so Keynote decks have no notes panel.
- Safari opens large files slowly (about 10 s for 300 MB).
- Keynote output has only been checked when opened from a local file (`file://`), not from a web server.
