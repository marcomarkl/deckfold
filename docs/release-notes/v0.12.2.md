Sixteenth pre-release of deckfold: a presentation uses less memory in Chrome, because the text of an embedded file is let go once it is decoded.

## What changed

- deckfold embeds every picture, video and font as Base64 text. The browser decoded such a file when it was first needed and kept the result, but the text stayed in the page as well, so every file in use was held twice; a file that a player loads itself, as the Keynote player does, was decoded again each time. Now each file is decoded once, the result is kept, and its text is emptied. In Chrome 158 the page of the 300 MB test file used 286 MB instead of 405 MB after going through every slide, and all processes of the browser 448 MB instead of 782 MB; for a 65 MB deck all processes used 499 MB instead of 568 MB. On the start screen the peak right after loading is the same as before, and Chrome gives the text back by itself within 30 s. In the WebKit engine that Playwright drives, emptying the text changed nothing; Safari itself was not measured. The measurements are in `docs/spikes/S3-large-files.md`.
- The files themselves do not change; a file converted before gets this with `--refresh`.

## What is tested

- Memory, measured on a MacBook Pro with macOS 27.2.1 before the change was built: emptying the text by hand gave back 302 MB more than a control run for the 300 MB file in Chrome, 66 MB for a 65 MB deck and 16 MB for a 13 MB Keynote export; in WebKit 0 to 1 MB. The figures under "What changed" were measured again with the old and the new code on the same files.
- A browser test in Chrome, Firefox and WebKit checks that the start empties decoded files and that every file still gives its bytes, also when it is asked for again. It fails on the code of v0.12.1.
- In Chrome and WebKit on a Mac: the 179 browser tests, among them the Keynote tests, whose player loads its files itself, and the test of the 300 MB file.
- The six binaries build with `scripts/release.sh` on a Mac (19.3 MB to 21.2 MB), and the smoke test passes with the one for macOS (arm64).
- The CI: `go vet`, the Go suite and the smoke test on Linux, Windows and macOS (x64 and arm64), and the browser tests with the public decks in Chrome on Linux and Windows and in Firefox on Linux.

## Not tested yet

- Memory in Safari, and in Chrome on Windows and Linux.
- The rows of `docs/manual-test.md`, among them the two-screen checks.
