Fifth pre-release of deckfold: a new way to present that works the same in every browser and on every machine.

## Why

With two screens in Chrome, the audience window of v0.3.0 could open on the laptop instead of the projector, at "Start" and at "Reopen". Without the window management permission, Chrome puts every popup on the screen of the window that opens it. Whether the permission is there depends on the browser profile and is not visible to the page. Safari and Firefox never place windows, and no browser reports reliably which screen a window is on. deckfold therefore no longer places windows and does not check where they are.

## What changed

- **The window you open the file in is the presentation.** It shows a start screen first: the title, a large preview of the chosen slide as it looks after all its steps, a strip of all slides to choose where to start, and the settings. "Start" or Enter begins the presentation in this window.
- **The presenter view is a second window you switch on.** It opens next to the presentation; drag one of the two windows to the other screen. deckfold asks for no permission and shows no hint about the screens; full screen can always be chosen.
- **Previews show whole slides.** The presenter view shows the current slide and the next slide, each as it looks after all its steps, without playing the builds. Previews keep the deck's aspect ratio, so a narrow presenter view no longer shows several slides of a claude.ai deck at once.
- **The presenter view's settings change while it runs:** which panes it shows (switches in the status bar at the bottom), the size of the notes (A− and A+), the target duration, and the size of the panes by dragging the dividers. Its slide overview is a strip above the status bar: a click jumps, the arrows only scroll it. Auto mode, its interval and loop are set on the start screen; interval and loop can be set only with auto mode on. The settings dialog and the screen dialog are gone.
- **Target duration as minutes:seconds,** completed as you type it: "20" becomes 20:00, "5:3" 05:03, "1:75" 02:15. The full-screen button of the presenter view reads "Window" while it is in full screen.
- **One Escape ends the presentation**, also in full screen in Chrome and Edge (Keyboard Lock); Safari and Firefox still need two. The end returns to the start screen with the last slide chosen, and reloading the window keeps the slide chosen or shown last; the presenter view stays open, so the next start needs no dragging. The black end slide after the last slide stays until the presentation is ended.
- **claude.ai slides with steps that run by themselves:** moving on before such a run had finished put the player one step further instead of on the next slide, so the presentation and the presenter view showed different slides. deckfold now jumps to the next slide in that case. Back on such a slide goes to the slide before, because the player would run the steps again by itself.
- **Mouse and trackpad keep to deckfold's slide.** A click on the slide moves on like the key for next; the wheel and swipes do nothing. Before, the claude.ai player moved by itself on a click, the wheel or a swipe, the presentation and the presenter view then showed different slides, and back no longer reached the first slide. deckfold also compares the slide the player shows with its own once a second and brings the player back if they differ.
- **The audience pane** below the current slide shows what the audience sees whenever that is not the whole slide: a step before the last one, a black or white screen, the end slide. It can be switched off like the other panes.
- **Enter only starts the presentation.** During the presentation it does nothing; digits and Enter still go to a slide. The start screen lists every key as it is set, in groups.
- **Previews paint no step in between:** they reach the slide and all its steps at once, and a preview stays hidden until it shows its slide.
- **The presenter view fits narrow windows:** the panes stand one below the other and scroll, and the bar stays one line. Closing the presentation window closes the presenter view.
- **The source player runs only after "Start".** Before it, no video or audio plays and no automatic step runs under the start screen. Every start begins at the chosen slide; back on the first slide does nothing.
- The configuration has new fields `presenter.layout` for the size of the panes (with `audience` for the audience pane) and `presenter.targetSeconds` for the target duration; the element `audience` is new, and Enter is no longer a key for `next`; `presenter.targetMinutes` from older files is read and converted, `screens.rememberChoice` is accepted and ignored.

Converted files get the new controls with `deckfold --refresh <file.html>`; the slides stay unchanged. The settings stored in the file are kept, keys and settings added since then get their defaults, and a key list or element list that is still the default of an older version becomes the current default (before, a file made by an older version kept its old key list, and a missing setting reset all of them).

## What is tested

- Browser tests for the start screen (preview, strip, start slide, keys, the slide kept over a reload), for the source player being inactive before "Start" and again after the end, for the presenter view opening without a position, following the start slide and reconnecting after a reload, and for Escape with Keyboard Lock, also in the presenter view in full screen. Further tests check that no screen permission is asked for, that the previews of a claude.ai and a PowerPoint deck show the current and the next slide after all their steps without running animations, also in a narrow presenter view, and the time: elapsed, pause, reset, target and time left, and the minutes:seconds input. They run in Chrome, a part also in WebKit, and the PowerPoint tests in Firefox in the CI.
- Speed in Chrome on an Apple silicon MacBook: a 300 MB file shows its start screen right after the browser has read it (about 1 s), and the first slide about 0.3 s after "Start"; a PowerPoint deck with 200 slides shows its start screen in about 0.15 s.
- A manual test with two screens and a real keyboard before the release.
