Fifteenth pre-release of deckfold: the time in the presenter view stands still when the show ends, and Escape leaves full screen in the presenter view before the start and after the end.

## What changed

- Once started, the time in the presenter view never stopped: after the end of a show the start screen came back, and the time ran on. It now stands still when the show ends and runs on from there when the show starts again. T and the button beside the time set it back to zero, and pausing works during the show only.
- In full screen every window of deckfold locks Escape, so that one Escape ends the presentation. Before the start and after the end the presenter view has no show to end, and it swallowed the key, so its full screen could only be left by holding Escape or with the full-screen button. There Escape now leaves full screen. During the show it ends the show as before.

## A fault of Chrome on a Mac

In Chrome on a Mac with two screens, the first full screen of the presenter view after it was dragged to the other screen can end at once: the window jumps and stays a window, and a second click on the full-screen button works. Safari, with the same file and the same moves, goes to full screen at the first click. A log in both windows showed that after the drag Chrome placed the window, and even the click on its button, on the screen the window came from, while the window lay fully on the new one; full screen ended about 90 ms after it began, and only then did Chrome name the new screen.

A page cannot correct this. `window.moveTo` keeps the window on the screen Chrome believes it is on (5 of 5 moves to the other screen ended at the edge of the old one), `requestFullscreen()` uses up the click, so a second attempt without a new click is refused, and asking for full screen on the screen of the click would use the same wrong coordinates. Two attempts that were tried and dropped are described in `docs/spikes/S2-file-protocol.md`. What helps: click the full-screen button a second time, or move the window a little on the new screen before the first click.

## What is tested

- Browser tests for each change: the time stands still after the end and runs on from that value with the next start; Escape leaves full screen in the presenter view before the start and after the end, and ends the show during it. Both fail on the code before their change (the time went from 00:03 to 00:06 in 2.5 s after the end; the presenter view stayed in full screen after Escape before the start).
- Escape in real macOS full screen, in the installed Chrome driven by raw clicks and keys: before the start and after the end the presenter view returns to a window, during the show Escape ends the show and the presenter view stays in full screen.
- The test of the time failed once on the Windows runner and passed 100 of 100 repeats there on the code before and after the change of Escape. When it fails now, its message carries the state of both windows.
- In Chrome and WebKit on a Mac: the 177 browser tests (152 in Chrome, 25 in WebKit).
- The six binaries build with `scripts/release.sh` on a Mac (19.3 MB to 21.2 MB), and the smoke test passes with the one for macOS (arm64).
- The CI: `go vet`, the Go suite and the smoke test on Linux, Windows and macOS (x64 and arm64), and the browser tests with the public decks in Chrome on Linux and Windows and in Firefox on Linux.
