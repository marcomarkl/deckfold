# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Rules

- This is a public repository. Everything that can be read publicly is written in English: README, CLAUDE.md, `docs/`, code comments, test names, CLI output and error messages, commit messages, and texts on GitHub. Write these texts following the `anthropic-skills:vermenschlichen` skill (load it first; apply its rules to English). Conversations with the maintainer stay in German. `internal/repocheck` fails on German umlauts, sharp s and the German opening quotation mark (U+201E) in tracked files outside the German UI strings in `runtime/src/00-core.js`; it does not catch German without these characters.
- The browser UI stays bilingual: German and English strings live side by side in the `TEXT` table in `runtime/src/00-core.js`, and the language follows the browser.
- UI texts stay short: labels instead of explanations, hints in a status line rather than in paragraphs or banners, key help as key chips. No area of the start screen or the presenter view stays empty while it is in use: an empty area reads as a fault, so it shows what it stands for, even when that repeats another area. Check a new or changed screen with a screenshot at 1280 × 800 before reporting it done.
- Test data, work folders and intermediate files stay inside the project, in git-ignored folders (`tests/.out/`, `testdata/`). Write nothing to the maintainer's other folders (`~/Documents`, the home folder, `/tmp`), also not for a quick check; convert or copy private decks only into `tests/.out/`. The one exception: `scripts/pptxref/pptxref.sh` copies the bundled fonts into `~/Library/Fonts` for the duration of a run and removes them at the end.
- `testdata/` holds private sample decks and is never committed. Do not put file names, slide content or notes from it into code, tests, docs or commits. Tests read expected values (slide counts, notes) from the deck metadata.
- Fix a fault at its cause. Establish the cause first, with a measurement or a test that fails on the old code (and research or Context7 where needed); a change that only hides the symptom, such as moving a window back or raising a test limit, is not a fix.

## What deckfold is

A Go CLI that turns presentations into one self-contained HTML file that runs offline: PowerPoint files (also Google Slides via its PPTX download) and the HTML exports of Keynote and claude.ai. For HTML exports the source player stays unchanged; PowerPoint files are rendered by deckfold into an HTML deck with its own player. deckfold embeds every asset and adds its own control layer (runtime in JS): start screen, presenter view, auto mode, keyboard and clicker control. Design decisions E1 to E16 and P1 to P18 (PowerPoint) are listed in `docs/decisions.md`.

## Commands

```bash
go generate ./runtime          # bundle runtime/src into runtime/dist (after EVERY change in runtime/src or runtime/pptx-player)
node --check runtime/dist/deckfold.js && node --check runtime/dist/pptx-player.js   # syntax of the bundles: the bundler concatenates without parsing, so a syntax error otherwise shows up only as browser tests timing out at the start screen
go build ./...
go vet ./...
go test ./...                  # includes a test that runtime/dist matches runtime/src
go test -run TestGoldenKeynote -v ./cmd/deckfold
DECKFOLD_OFFLINE=1 go test ./...   # skips the golden test that downloads remote fonts
go run ./cmd/deckfold <deck.html|export-folder|deck.pptx> -o /tmp/x.html --force
go run ./cmd/deckfold x.html --content x.json   # the slide text of a finished file (or x.md)
go run ./scripts/pptxgen          # rewrite the public PowerPoint feature decks in fixtures/pptx/src
(cd scripts/three && go run .)    # rebuild runtime/dist/three.js (pinned three.js, own Go module with esbuild)
DECKFOLD_BUNDLED_FONTS=1 go run ./cmd/deckfold deck.pptx -o /tmp/x.html --force   # ignore installed fonts
scripts/release.sh 0.1.0       # six binaries (darwin/windows/linux x amd64/arm64, CGO_ENABLED=0) into dist/
```

Browser tests (Playwright, folder `tests/`). `e2e/setup.mjs` builds the binary and writes all test outputs to `tests/.out/` (including a file of about 300 MB for the performance test, created only on the first run) plus `corpus.json` with the corpus entries it found. Because `setup.mjs` rewrites `tests/.out` on every run, run only one Playwright run at a time. A script that opens outputs in `tests/.out` directly sees the runtime of the last setup: after a change in `runtime/src`, run `go generate ./runtime`, rebuild `tests/.out/deckfold` and convert the deck again first. For each format it takes a public deck from `fixtures/` first, then the local corpus `testdata/`, and for Keynote finally a hand-made export in `tests/.out/keynote/<name>/`. The preview tests also need a claude.ai deck with builds (`claudeSteps`, converted to `claude-steps.html`): the first such deck in `fixtures/claude/` or `testdata/claude/`, otherwise a copy placed in `tests/.out/claude-src/`:

```bash
cd tests && npm install && npx playwright install chromium webkit
npx playwright test
npx playwright test e2e/claude.spec.mjs -g "recovery" --project=chrome
```

Projects: `chrome` (channel `chrome`, autoplay without a gesture allowed, SwiftShader so that WebGL works without a GPU), `webkit` (only `webkit.spec.mjs`, the fallback browser) and, outside macOS, `firefox` (only `pptx.spec.mjs`; the Playwright Firefox does not start on macOS 27.2). Tests pick controls by their `data-df-…` attributes (`[data-df-start]`, `[data-df-presenter]`, `[data-df-fs]`, `[data-df-el="notes"]` …), never by text, because the UI language follows the browser. `helpers.mjs` has `startScreen`, `solo` (start without the presenter view) and `present` (switch the presenter view on, start; returns the presenter window, while `page` is the presentation). When a test checks where the show is, in the presentation or in a preview, compare with what the source player shows (the `.deck-slide` without `data-off` for claude.ai, `.df-pptx-slide.df-on` or `__dfPptx.state()` for PowerPoint, the player's slide change event for Keynote), not only with `__deckfold.audience.state()`, which is deckfold's own model. A test moves the presentation through deckfold (`__deckfold.audience.act('state', {slide, step})`, `act('next')`), not through the player (`__dfPptx.goTo/next/showAll`, `#n`): the runtime drives the player through that API, and the show window brings a player that went elsewhere back to its own state within a second, so a direct call fails only now and then. Call the player directly only on the slide deckfold already shows, or in a test of that check. A test whose last action makes a window reload or navigate (ending the presentation with Escape or "End show"; `page.reload()`) waits until the page is ready again (for the start screen `[data-df-start]`) before it finishes: closing the browser context during a reload hangs until the test times out. `helpers.mjs` has `need(kind)` to skip without a corpus entry and `expected(page, ops)` to compute expected states with the runtime's own model.

CI (`.github/workflows/ci.yml`) runs on every push to main, every pull request and every `v*` tag: `go vet`, `go test` and the smoke test on Linux, Windows and macOS (x64 and arm64), on Linux also as an unprivileged user. The `browser` job runs the browser tests with the public decks in Chrome on Linux and Windows and in Firefox on Linux; tests that need the local corpus are skipped there, and a release waits for this job too. Run the smoke test locally with `go run ./scripts/smoke -bin <binary>`. A `v*` tag also builds the six binaries with `scripts/release.sh` and publishes them as a pre-release. To release, add `docs/release-notes/<tag>.md` first (the job stops without it), then push the tag. Sizes in release notes come from the binaries of `scripts/release.sh` (`dist/`, built with `-trimpath -ldflags "-s -w"`) or from the published assets, not from a plain `go build`, which keeps symbols and debug information. The two-screen checks that CI cannot do are in `docs/manual-test.md`. A browser test that fails only in CI (Firefox does not start here) first gets a failure message that carries the measured state, so that the cause can be read from the CI log; then the cause is fixed. The Linux runners have no sound device, so the workflow gives the browser a PulseAudio null sink (without it, Firefox stops an audio clip after about two seconds).

Every output contains the runtime bundle, and the bundle contains marker strings such as `text/df-css`, `text/df-deferred`, `data-df-` and `deckfold:`. When a test asserts on generated HTML, count tags or attributes with `internal/htmlscan` (see `cmd/deckfold/main_test.go`), never substring occurrences in the whole file. This holds for every HTML file that contains the runtime bundle or the PowerPoint player, including the intermediate deck from `internal/pptx/deck`: the player's own comments contain `df-pptx-slide`, and escaped slide text can look like an attribute. Check text only inside the element it belongs to.

Local corpus layout (not in the repository): `testdata/claude/*.html` and `testdata/keynote/<export>/index.html`. The public PowerPoint decks are in `fixtures/pptx/` and are committed; `fixtures/pptx/powerpoint/` holds the two decks whose effects and transitions PowerPoint added itself (`scripts/pptxref/ppdecks.sh`). Keynote exports contain Apple's player and stay local: `scripts/keynoteref/keynoteref.sh` describes the export into `tests/.out/keynote/<name>/` (Keynote 15.4 does not open files there through AppleScript, so it is done by hand).

## Architecture

**Pipeline (Go):** `cmd/deckfold/main.go` (flags, precedence CLI > `--config` > defaults, `--refresh`, exit codes 0/1/2/3) → `internal/detect` (load the input, choose the adapter) → `internal/embed.Convert` (shared conversion) → output.

- **Fidelity:** HTML is never re-serialized. `internal/htmlscan` reads tags with byte offsets; every change is an `internal/patch` patch on the original bytes. Inline scripts and the deck JSON stay byte-identical (the golden tests check this).
- **Deferred activation:** `embed` makes everything inactive that the browser would load or run right away: asset attributes become `data-df-<attr>` with the placeholder `deckfold:<hash>`, stylesheets become `<script type="text/df-css">`, executable scripts get `type="text/df-deferred"` (data scripts such as `application/json` stay). The runtime loader activates them in the original order.
- **Output layout:** the runtime block sits right after `<meta charset>` (which must stay within the first 1024 bytes), between `<!--deckfold:runtime:begin/end-->`; `--refresh` swaps this block (`internal/inject`), for PowerPoint decks also the player and three.js, and computes the content block again. Before `</body>`: `#df-meta` (deck metadata, shim table, deckHash), `#df-content` (the content model, see below) and the asset blocks `<script type="application/octet-stream" id="df-a-<hash>-<n>">` (Base64, at most 6 MB of binary data per block, deduplicated by content hash in `internal/assets.Store`).
- **CSP** (`internal/csp`): extended (`blob:`, embed origins), embedded Google hosts removed. If the source uses `'unsafe-inline'` without hashes or nonces, NO hashes may be added (that would block the source scripts). The loader decodes with `atob`, never with `fetch` or a worker (the claude.ai CSP forbids both).
- **Content model** (`docs/content-model.md`, decision E16): `#df-content` holds, for every slide of the metadata, its text blocks with a role, the step in which each shows and links to other slides. Each adapter reads it in `Content(src, meta)`; `adapter.Finish` sets the titles from the slide labels and cleans the text. A role or a title comes only from what the source marks, never from the size or the place of a text. `Content` reads through its `ContentSource` (the document plus `Load(ref)`), because `--refresh` calls it on the finished file: there `Load` resolves through the shim table to an embedded asset (`inject.ReadAssets`) and never reads the file system. When the content cannot be read, the conversion and `--refresh` go on without the block and say so. `internal/content` reads the block back and writes JSON or Markdown for `--content`; slide text is escaped in the Markdown.
- **Boundaries:** `assets.Resolver` resolves only inside the input folder (symlinks checked, `--allow-outside` as the exception), in stages: exact, URL decoding, NFC/NFD, case-insensitive (every fix is reported as a warning). `assets.Fetcher` refuses private, loopback and link-local targets.

**PowerPoint** (`internal/pptx`): `main.go` sends `.pptx`/`.ppsx`/`.pptm` (and ZIP or OLE files without an HTML extension) through `pptx.Convert` into a temporary folder before `detect.Load`; from there the regular pipeline runs with the `pptx` adapter.
- `opc` (ZIP with size and path limits, relationships), `xmltree` (element tree by local names; `mc:AlternateContent` is resolved while parsing, only the PowerPoint 2010+ namespaces count as supported), `model` (slides, layouts, masters, themes, placeholder inheritance slide -> layout by idx -> master by type), `geom` (the unchanged Ecma `presetShapeDefinitions.xml` with a formula evaluator), `fonts` (cascade embedded -> installed -> bundled Carlito/Liberation, fsType, subsets renamed because of the Reserved Font Names, own `cmap` for subsets; `fonts/mtx` decompresses MicroType Express fonts and has a small encoder for tests; right-to-left text and complex scripts are measured with go-text/typesetting and their fonts embedded whole), `render` (one SVG per slide; every slide shape is `<g data-sid>`, paragraphs are `<g data-p>`, words and letters of word or letter builds are groups inside them; text layout is deckfold's own; 3D shapes get an SVG base drawing plus their 3D data for the player; while drawing it collects the text blocks of the slide for the content model (`blocks.go`, decision P18) and writes links to other slides as `data-df-jump`), `emf` (EMF and WMF), `anim` (timing -> steps, triggers, iterate), `deck` (writes `index.html`, `#df-pptx-deck` with the blocks of every slide since its version 2, the player between `<!--deckfold:pptx-player:begin/end-->` and, only for decks that need WebGL, three.js between `<!--deckfold:pptx-three:begin/end-->`).
- The player (`runtime/pptx-player`, bundled into `runtime/dist/pptx-player.js`) belongs to deckfold, so the JS adapter drives it through `window.__dfPptx` (`goTo`, `next`, `prev`, `showAll`, `state`, and `interactive` and `linkOf` for clicks); this is the exception to the rule below about synthetic keys. `goTo` jumps without animation, only `next` animates; previews never animate or play media. `--refresh` also replaces the player code and three.js. The player draws 3D shapes and 3D charts with three.js over the SVG base drawing (`07-three.js`), the tile transitions with WebGL (`08-tiles.js`) and the 3D transitions, Morph and the other dynamic transitions with CSS (`10-player.js`); without WebGL it keeps the base drawing and fades.
- Text from the presentation is data: everything is escaped, links are limited to http, https and mailto, SVG pictures are referenced through `<image>`, asset names are content hashes. `TestHostileDeck` checks this.
- Tests: `internal/pptx/pptx_test.go` (structure of the feature decks), `tests/e2e/pptx.spec.mjs` (browser; expected animation states come from `fixtures/pptx/src/animations.spec.json`, the expected content model of the content deck from `content.spec.json`; the generator writes both from its own description of the decks, so a test never compares the converter with itself), `tests/e2e/pptx-fidelity.spec.mjs` (SSIM against PowerPoint images in `fixtures/pptx/ref/`, threshold 0.95, exceptions with a reason in the file). PowerPoint reports a deck as damaged when a 2010+ transition is not written in exactly its own form (see `fixtures/pptx/README.md`). After changing a feature deck, run `go run ./scripts/pptxgen` and then `scripts/pptxref/pptxref.sh` with only the names of the changed decks (never without arguments over all decks: PowerPoint rewrites the metadata of every deck it saves, and every deck costs access dialogs); otherwise the hash check in the fidelity test fails. Convert test decks with `DECKFOLD_BUNDLED_FONTS=1` so that the output does not depend on the machine.

**Adapters** (`internal/adapter/{claude,keynote,pptx,generic}`, Go side): `Detect`, `Collect` (files loaded at runtime through computed paths, which end up in the shim table), `Meta` (slides, steps, auto flags, delays, notes, thumbnails), `Content` (the content model). Each format also has a JS adapter in `runtime/src/20-model.js`. To add a format, follow `docs/adding-a-format.md`.
- claude.ai: detected by `meta[name^="hz:"]` + `#deck-motion`; notes come from `data-speaker-notes`; the player advances auto steps itself. The content is read with the tokenizer of `golang.org/x/net/html`, because `htmlscan` records start tags only: a block is the text of the innermost block element, and it shows from the step in which neither it nor an element around it is in `steps[].hidden` any more (the ids there are `data-frame-id` values). Its slide counter `.deck-pager` stays in the HTML (the player looks it up) and is hidden by the runtime CSS. Strict structure check; an unknown structure is an error.
- Keynote 15.4 (export format 1.2): detected by `assets/header.json(p)` + `assets/player/main.js`. The whole `assets/` folder is embedded, because the presentation on `file:` uses JSONP/PDFP while the srcdoc previews load `.json`/`.pdf`/CMaps through XHR/fetch. No notes panel (Keynote exports no notes). The only text in the export is what the slide JSON lists for screen readers (`events[].accessibility`), without roles and in the order of the export; that is the content. Its blocks have no step: the list is not what is visible in a step (objects of later builds are in it from the start, and an event can leave out visible paragraphs). Links to other slides are in `events[].hyperlinks` (`url` such as `?slide=next` or `?slideid=<id>`, and `targetRectangle` in slide units): `Meta` puts them into `deck.extra.links` for the runtime, and `Content` sets the jump on the block with exactly the same rectangle. Details and key codes: `docs/spikes/S1-keynote.md`.

**Runtime** (`runtime/src/*.js`, bundled in name order into one IIFE; the bundler emits ASCII only). Roles (`00-core.js`, decision E14): `show` (the window the file was opened in: the start screen of `35-start.js` with only the CSS activated, then, after "Start", the presentation of `40-audience.js` with the source scripts; owns the state and the auto timer; the end reloads it back to the start screen), `presenter` (popup the start screen opens with `window.name = "df-presenter:<token>"`, kept in `sessionStorage` too; never runs the source scripts), `preview` (srcdoc iframes in the start screen and the presenter view; get their assets through `parent.__deckfold.assets`). deckfold never places windows and does not check where they are, in any browser (decision E14; the reasons are in `docs/spikes/S2-file-protocol.md`); full screen can always be chosen. Previews always have the deck's aspect ratio and show a slide after all its steps (the audience pane of the presenter view shows the step the audience sees): in the role `preview`, Web Animations are finished as soon as they start and CSS animations and transitions get a duration of 0 (class `df-still`, not for PowerPoint, whose `goTo` does not animate). A preview reaches its state within one task, so no step in between is painted (claude.ai: `replaceState` and a dispatched `hashchange`, through a neighbouring slide, then every step; `jumpAtOnce` in `20-model.js`), and its iframe stays hidden until it shows its first state. Keynote's slide number display, which the player shows while deckfold jumps by digits, is hidden in previews.
- `10-loader.js`: placeholders to blob URLs, activate styles and attributes, shim for `setAttribute`, `src` setters, XHR, fetch, Worker and `<style>` inserted at runtime, start the deferred scripts and replay a missed `DOMContentLoaded`/`load`.
- `20-model.js`: state model (slide, step). The runtime keeps the state itself and drives source players only through synthetic keys (with `keyCode`) or `#n`; never read internal player variables. The one thing read from a player is which slide it shows (`adapter.shown()`: the `.deck-slide` without `data-off`, `__dfPptx.state()`, the index of Keynote's slide change event): the show window compares it with its state after every move and once a second and jumps back when they differ (decision E15). Clicks, the wheel and touch moves are taken in the capture phase before any source script (`DF.installPointer` in `30-keys.js`): a click is "next", the wheel and swipes never reach the player. A click on a link to another slide (`adapter.link`: for PowerPoint the `data-df-jump` of the converter, for Keynote the link whose rectangle holds the click, mapped through the player's `#stage` element) is followed by the show window through its own state (`follow` in `40-audience.js`), so both windows go there; "next" and "prev" of a link mean slides. The PowerPoint player is deckfold's own and is driven through its API (see above). A negative entry in `delay` means "no source timing for this step". The model only holds states the player rests in (`next` and `prev` skip whole auto runs of claude.ai slides). A key press during an auto run moves the claude.ai player by one step only, so moving away from a slide with auto steps, and in previews moving onto one, is a jump through `#n` followed by single steps (`DF.drive`).
- `30-keys.js`: capture listeners on `window` are registered as soon as the runtime loads (before any source script); bound keys never reach the player, Escape included. While an overlay of deckfold is open, `DF.modalKeys` takes every key before these listeners act, so that Escape closes the overlay instead of ending the presentation and the arrows do not move the slides. Channel: `postMessage` with sender and token checks (no BroadcastChannel: messages do not arrive in WebKit).
- `35-start.js` / `40-audience.js` / `50-presenter.js`: the show window is the authority for the state; the presenter view sends commands to `window.opener`, buffers them while the show window reloads, and gets `init`, `state` and the heartbeat back. Commands and keys that arrive between "Start" and the player standing on the start slide are kept and carried out in order afterwards (`early` in `35-start.js`, `take` in `40-audience.js`); the presenter view already shows the show during that time. A control clicked with the mouse gives the focus back (`32-ui.js`), so that the keys never show a focus ring on it or press it. Before the start, commands from the presenter view change the start slide. Wake lock, full-screen fallback, offline placeholder for live embeds. `32-ui.js` holds the preview iframes, the slide tiles (built only when visible), `DF.slideStrip` (the strip with arrow buttons on the start screen and in the presenter view), the key chips and `DF.finder`, the overlay for search and outline over the content model (`DF.content`; the action `find`, `/` by default, and Ctrl+F or Cmd+F). The start screen searches the slide text only, because it may already be on the projector; the presenter view searches the notes too. The presentation itself has no search. Text from the slides goes into the list as text nodes only. When something fails on the maintainer's machine but not in a reproduction, get measured values from that machine before changing code: screenshots of both windows and what the console shows. For reproductions with Playwright see the pitfalls in `docs/spikes/S2-file-protocol.md` (popup blocking, `--window-position`/`--window-size`, clicks, full screen, the real mouse pointer). The click on "Start" is stopped and the source scripts start only after it, because a player that registers its listeners during the click would take it as "next"; the hash is cleared before the start, because the claude.ai player reads `#n` from the address.
- Settings: defaults from `#df-config`, differences in `localStorage` under `deckfold:<deckHash>` (Chrome shares `localStorage` across all `file://` pages).

Background measurements on `file://` behaviour (Window Management API, blob URLs in popups and iframes) and on large files: `docs/spikes/S2-file-protocol.md`, `docs/spikes/S3-large-files.md`.

## PowerPoint automation

`scripts/pptxref/pptxref.sh` drives PowerPoint through AppleScript to make the reference images (see `fixtures/pptx/README.md` and `docs/spikes/S4-powerpoint-reference.md`). PowerPoint's sandbox shows modal "Grant Access" dialogs for files it has not opened before, and the maintainer has to confirm them; a folder grant does not stop them, and macOS blocks writing into PowerPoint's container. Tell the maintainer before every run, keep the fixed work folder `tests/.out/pptxref` with fixed file names, and do not query PowerPoint through AppleScript just to check its state (that starts it again). PowerPoint does not answer Apple events while a start dialog is open; close it first. Quit PowerPoint afterwards when no presentation is open.

## Keynote automation

Never close a Keynote document through AppleScript (Keynote crashes). Keynote is sandboxed and cannot export into `/private/tmp`; export into a git-ignored folder inside the project (for example `tests/.out/keynote`). Keynote 15.4 does not open files in `tests/.out` through AppleScript (open returns nothing and no access dialog appears; checked on 2026-11-07), so these exports are made by hand. A native Keynote test deck with builds, video, audio and self-playing mode is still missing.

If you launched Keynote (or any other app or long-running process such as a Playwright browser or a local server) during a task, stop it before you report the task as done. Stop it by its own handle (the background task, the browser object, its PID), never with a pattern such as `pkill -f ms-playwright`: other projects on this machine run Playwright browsers too. For Keynote, first check that no document is open (`osascript -e 'tell application "Keynote" to get name of every document'`), then quit it with `tell application "Keynote" to quit`. Use the name of the installed app; on some Macs it is "Keynote Creator Studio". Never use `close` on a document (see above).
